# 838 — Push Dominoes

- **날짜:** 2026-07-15
- **링크:** https://leetcode.com/problems/push-dominoes/
- **난이도:** Medium

## 풀이

```python
from collections import deque
class Solution:
    def pushDominoes(self, dominoes: str) -> str:
        answer = list(dominoes)
        visited = [-1] * len(dominoes)
        queue = deque()
        for i, dominoe in enumerate(dominoes):
            if dominoe == "L":
                queue.append((i, "L"))
                visited[i] = 0
            if dominoe == "R":
                queue.append((i, "R"))
                visited[i] = 0
        
        cur_depth = 0
        while queue:
            cur_depth += 1
            for _ in range(len(queue)):
                cur_idx, cur_dir = queue.popleft()

                if cur_dir == "L":
                    if cur_idx-1 < 0:
                        continue

                    if answer[cur_idx-1] == ".":
                        answer[cur_idx-1] = "L"
                        visited[cur_idx-1] = cur_depth
                        queue.append((cur_idx-1, "L"))
                    elif answer[cur_idx-1] == "R":
                        if visited[cur_idx-1] == cur_depth:
                            answer[cur_idx-1] = "."

                elif cur_dir == "R":
                    if cur_idx+1 >= len(dominoes):
                        continue

                    if answer[cur_idx+1] == ".":
                        answer[cur_idx+1] = "R"
                        visited[cur_idx+1] = cur_depth
                        queue.append((cur_idx+1, "R"))

        return ''.join(answer)
```

## S — Situation (문제가 뭔가)
도미노들이 놓여있는 순서가 `dominoes`로 주어졌을 때, `L`로 쓰여진 도미노는 왼쪽으로 `R`로 쓰여진 도미노는 오른쪽으로 쓰러지고 `.`들은 가만히 서 있는 도미노라고 한다. 최종적으로 모든 도미노가 움직였을 때의 상태를 문자열로 반환하는 것이 문제이다. 이때, 왼쪽과 오른쪽으로 쓰러지는 도미노가 만나면 멈추게 된다.

## T — Task (왜 까다로웠나)
N은 최대값은 `10^5`으로 `O(N^2)`이면 시간 초과가 날 위험성이 존재해서 그 이하의 복잡성을 갖는 알고리즘을 선택해야 했다.
이때, 모든 도미노가 동시에 떨어지고 다음 도미노로 넘어갈 때 같은 시간이 걸린다는 점에서 계층 구조를 떠올렸고, depth를 포함한 BFS 알고리즘을 사용하기로 했다. 특히 동시에 L과 R이 도달하는 경우를 파악하기 위해서 현재 위치에 처음으로 도달한 시점과 현재 시점이 같은지를 파악하는 로직을 추가하였다.

## A — Action (접근과 대안)
- **검토한 대안들:**
  - A. BFS + Depth: O(N)의 시간/공간복잡도, 구현 간단 
  - B. Two Pointer: O(N)의 시간복잡도, O(1)의 공간복잡도, 구현 복잡
- **각 대안의 트레이드오프:** Two Pointer의 경우 공간복잡도가 더 적지만, 엣지 케이스 등을 고려해야 해 한 번에 구현 방식을 떠올리기가 어려웠다. BFS + Depth 방식은 메모리를 더 사용하지만 그래프 순회 방식으로 같은 Depth의 도미노들을 처리해주면 되므로 구현이 조금 더 간편하다.
- **최종 선택과 근거:** BFS가 구현 용이성을 가져 BFS를 선택하였다. 

## R — Result (복잡도·한계)
- **시간복잡도:** O(N), 모든 셀이 최대 1번 큐에 들어갈 수 있음
- **공간복잡도:** O(N), 최악의 경우 모든 셀이 동시에 큐에 존재
- **Correctness 근거:** `cur_dir == "R"` 분기에서 `answer[cur_idx+1] == "L"` 분기는 항상 죽은 분기가 된다. 도미노 배열의 왼쪽부터 큐에 들어가므로 R과 L이 서로 마주보고 있는 상황이라면 R이 항상 L보다 먼저 수행되게 된다.
- **엣지케이스:** 도미노가 하나도 없는 경우 `..`는 큐에 셀이 포함되지 않으므로 문제가 없다. 맨 앞이 L이거나 맨 뒤가 R인 경우는 `continue`로 처리하고 있어서 문제가 되지 않는다. `RL`의 경우에는 `cur_depth` 조건에 해당이 되지 않아 문제가 없다.
- **한계:** 도미노가 쓰러지는 속도가 다르면 BFS 방식을 사용할 수는 없고 Priority Queue를 사용해야 했을 것이다.
